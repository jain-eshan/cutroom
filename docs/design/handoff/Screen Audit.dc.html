Design QA podcast-editor / src · 8 screens · 9 systematic · 30 screen-level

The tokens landed. The screens didn't.

Every colour, radius and font in index.css is transcribed faithfully from the handoff — OKLCH, both themes, the right comments in the right places. Almost none of it reaches the components. The screens are built out of Tailwind's defaults with token names sprinkled on top: nine ad-hoc button recipes, a font size the scale doesn't contain used twenty times, three pulsing animations the system forbids, and raw black where the video-plate tokens exist precisely to prevent it. Nothing here is a redesign. It is the design system, applied.

WHAT IS ALREADY RIGHT

Worth saying before the list, because it is the part that is hard to get back once it's lost. The voice is excellent — every automatic decision states what it did and why in one clause, errors follow the four-beat order with the raw string in the mono well underneath the plain line, numbers are specific, there is no "AI", no emoji, no exclamation marks. Monospace discipline holds: timecodes, sizes, filenames and shell strings are mono, prose never is. The terminal well stays dark in both themes with the reasoning written in the comment. The 55%-black timecode pill over the video, opacity-as-state on older transcript lines, and the global box-sizing with its timeline-overflow comment all match spec exactly. The honest unbuilt artefacts on Publish are intact. Keep all of it.

Nine systematic fixes

Each of these is one cause showing up on five or six screens. Fixing them here is worth more than fixing them screen by screen, and most of the per-screen list below disappears when they land.

BRAND RULE S1 · index.css The base theme is inverted — the app ships light

The system's own tokens/colors.css says it in a comment on line two: ":root is the DARK app theme (the product's primary surface)." The app does the opposite — light values sit on @theme, dark is the override. So a light-OS user gets the marketing theme as their editor, and every screenshot, doc and first-run demo taken on a default machine shows the wrong product. It also means the video plate and terminal well — surfaces designed for a dark surround — are the odd ones out by default rather than at home.

Keep system mode; just flip which side is the base. Dark on @theme, light behind an explicit opt-in plus a light-OS media query. One block moves; no values change.

@theme { /* the dark values, verbatim as they are today */ }

@media (prefers-color-scheme: light) {
  :root:not([data-theme="dark"]) { /* the light values */ }
}
:root[data-theme="light"] { /* the light values */ }
BRAND RULE S2 · index.css Seven token families are missing, so screens invent them with alpha

"Emphasis borders use the accent at 45% alpha (--accent-edge)." That token doesn't exist in @theme, so six places write border-accent/45 and border-warn/45 by hand. Same for the 12% drag ring, the 9% wash, the ok and warn edges, and the beta pair — which is why the BETA badge on Publish is grey control ink instead of the beta colour, and why the drop-zone drag ring is a hardcoded shadow-[0_0_0_6px_oklch(...)] string. Add the tokens and eight hand-mixed alphas collapse into named values.

/* add to @theme — identical in both themes, like --accent itself */
--color-accent-edge: oklch(0.74 0.16 52 / 0.45);
--color-accent-wash: oklch(0.74 0.16 52 / 0.09);
--color-accent-ring: oklch(0.74 0.16 52 / 0.12);
--color-ok-edge:     oklch(0.72 0.13 155 / 0.40);
--color-warn-edge:   oklch(0.62 0.15 30 / 0.50);
--color-beta:        oklch(0.84 0.13 88);
--color-beta-bg:     oklch(0.76 0.14 85 / 0.18);
BRAND RULE S3 · every screen The one shadow token is defined and never used once

"Elevation: one shadow token, no scale." --shadow-panel is declared correctly and appears in zero components. Every centred screen — setup, drop-in, processing, cast, publish, no-faces, failed — is a flat bordered rectangle on a nearly-identical ground, so the card never reads as a window sitting on a desk. Meanwhile the editor's shortcuts popover uses Tailwind's shadow-lg, which is the one place a shadow does appear and the one place it isn't the token. Add shadow-panel to all seven cards; swap shadow-lg for it.

BRAND RULE S4 · every screen Nine button recipes, and a font size the scale doesn't contain

There is no Button in src. Every button is written from scratch where it stands, and they disagree: the primary action is px-4 py-2 text-[13px] font-medium on five screens, secondaries are variously px-3 py-2, px-2.5 py-1.5, px-2 py-1 and a bare underlined text link. The spec's ladder is 11/15px · fs-meta · semibold · r-6 for primary; the code is one step too small, one weight too light, and on a size that isn't on the scale at all.

13px is the tell. The type scale is 19 / 18 / 16 / 15 / 13.5 / 12.5 / 11.5 / 11 — there is no 13. It appears about twenty times across five files, on button labels, card titles and input text, always where 12.5 (UI) or 11.5 (meta) was meant. text-[12px], text-[10px] and a text-[9px] BETA badge (under the 9.5 mono floor) have the same cause: no named sizes, so each author rounds to a habit.

BRAND RULE S5 · setup, processing, editor, publish Three pulsing animations, in a system that forbids motion

"No skeleton shimmer, no spinners, no entrance animations. Streaming transcript lines simply appear." The code has animate-pulse on the setup gate's indeterminate bar, on the processing bar whenever a stage reports zero, and on a blinking caret after the newest transcript line. That last one is the sharpest miss: it's a shimmer attached to the exact element the system names as the thing that should just appear. This is a tool for judging frames — a breathing UI next to a moving picture is a real usability cost, not only a rule.

Progress transitions are specified as 240ms linear — linear because it is a measurement. The bars use duration-300 with Tailwind's default ease. For genuinely indeterminate work, the honest answer isn't a pulse: it's a static track with the elapsed clock beside it, which the setup gate already renders one line below.

- animate-pulse   // three of them
- transition-[width] duration-300
+ transition-[width] duration-[240ms] ease-linear
BRAND RULE S6 · editor, processing, cast, publish Raw black and loose OKLCH literals bypass the plate tokens

"The video plate stays dark in both themes — a light surround changes how a person judges exposure and skin tone. Light mode lifts it only enough not to look like a hole punched in the window." --plate-a / -b / -ink exist for exactly this. The editor stage, the cropped-pane fallback, the split-pane dividers and the processing thumbnail all use bg-black. In dark mode you can't see the difference; in light mode it is the hole the spec describes, and the divider lines between panes vanish into it.

Three more colours are written as literals rather than tokens, which means they won't flip with the theme: the cast waveform bars (bg-[oklch(0.38_0.01_80)]), Publish's unchecked artefact ring (border-[oklch(0.42_0.01_80)]), and the media-error copy (text-white/80, where text is never alpha-muted — secondary ink is its own solid token). The bg-black/55 timecode pill over the video is the one correct use of black and should stay.

BRAND RULE S7 · cast, editor, drop-in, setup Unicode glyphs where the system draws shapes in CSS

Cutroom deliberately has no icon set. What carries meaning instead is colour and shape drawn in CSS: "the play triangle is a CSS border triangle inside a circle", "the upload glyph in the drop zone is a 14×2.5px rounded bar". The code substitutes characters — ▶ and ❚❚ for play/pause on both the cast and editor transports, ↓ in the drop zone, ✕ to delete an episode, ‹ › to step through flagged lines, ↗ on external links.

These aren't equivalent. Instrument Sans has no glyph for most of them, so the OS silently falls back — the pause bars render in a different typeface at a different weight than everything beside them, and the metrics shift between macOS, Linux and Windows. Publish's one real SVG has the opposite problem: it is drawn at strokeWidth 3.5, where the system's single icon rule is 1.5px stroke and no fill, matched to the 1px border weight. Rendered corrections are below.

OFF-SPEC S8 · every screen Disabled at 40%, and the inert state is never used

"disabled is 50% opacity on something that will become clickable. inert is a full-opacity control button with text-3 text for when there is nothing correct to click." disabled:opacity-40 appears twelve times; the inert treatment appears nowhere. So things that will never become clickable in this build — "Save a draft", the render percentage readout, "+ Note" — are drawn as dashed-border ghosts and 40% text, reading as broken rather than as deliberately not-yet. Publish adds a third and fourth value, opacity-70 on unbuilt artefacts and opacity-60 on unbuilt destinations, where the spec reserves 60% for optional dependencies and would have unbuilt carry a beta chip instead of a fade.

OFF-SPEC S9 · every screen Spacing snapped back onto Tailwind's 4px grid

"Lifted verbatim from the source. If a spec says 13px, write 13px." The outer card padding does this correctly everywhere — p-[26px], good. Inside them every gap reverts to a Tailwind default: gap-5 (20), gap-3 (12), py-2.5 (10), p-4 (16). The scale's deliberate half-steps at small sizes — 5, 7, 9, 11, 13, 18 — never appear, so the vertical rhythm is a fifth looser than drawn and the cards run taller than the source. Registering the scale as Tailwind spacing keys makes the correct value the easy one to type.

/* @theme — then gap-7, px-13, py-11 mean the spec's numbers */
--spacing-5: 5px;   --spacing-7: 7px;   --spacing-9: 9px;
--spacing-11: 11px; --spacing-13: 13px; --spacing-18: 18px;
--spacing-22: 22px; --spacing-26: 26px; --spacing-34: 34px;

Screen by screen

What's left once the nine systematic fixes land — the things specific to each screen's layout, hierarchy and copy. Ordered by the stage the user is in.

1 · Set up features/setup/SetupGate.tsx

The screen answers a different question than the design does. The design shows "Two things need to be running" as three status rows — this window, the processing service, captions-optional — each carrying its own state dot, with the command block nested under whichever row is blocked, and an inert "Waiting…" button. The code shows one heading plus a numbered ol of Hugging Face steps, and never tells the user what the machine's state actually is. Someone stuck here can't see which of the two things is wrong.

  • Adopt the three-status-row layout as the frame; keep the token steps as the nested detail of the row that needs them. Health already returns everything the rows need.
  • Numbered step circles are 22px control discs with mono numerals — correct, keep.
  • OutLink ends in a ↗ character; drop it and let it be a quiet button. The token input at 12px mono should be 11.5.
  • "Captions available" never appears as an optional dependency at 60% — so the one thing a user could fix before rendering is invisible until Publish tells them it's too late.
2 · Drop in features/upload/UploadScreen.tsx

Closest of any screen to the design, and the drag state is genuinely well built — 2px accent border, the 12% ring, the 40% dim on the content behind, and the "a second file would replace this one" line all match. Two structural differences: the content is centre-aligned where the whole product is left-aligned, and the heading is the wordmark "Cutroom" with a product pitch under it, where the design's is the task — "Start a new episode" with "One video of everyone in one frame, with one audio track. That's all it needs." The app doesn't need to introduce itself to someone who already opened it.

  • Left-align; logo at 24px with wordmark in the corner, not a 40px centred mark.
  • The local-first reassurance row sits on raised; the design puts it on chrome, one step down, so it reads as a footnote rather than a card.
  • "RECENT EPISODES" → "Pick up where you left off" as a section label, pinned to the bottom with margin-top:auto. Rows want a frame thumbnail, the name in sans, and mono status ("edited · not published") — the current row is name + locale date + a ✕.
  • Delete has no confirm and sits one pixel from Reopen. At minimum make it a quiet destructive button that appears on row hover.
3 · Read it features/upload/ProcessingScreen.tsx

The 22px mono accent clock with "about 1:20 left" beneath it is exactly right, and the live video thumbnail following the transcript position is a better idea than the design had. The problem is four identical progress bars stacked in a column: every stage looks equally live, so there's no reading of where the work actually is. The design gives each stage a state dot and a bar only on the active one — rendered above. Everything else on this screen is systematic: two pulses, bg-black on the thumbnail, 13px labels, no shadow.

  • "FACES FOUND" as a bare uppercase mono span → a section label reading "People found · 2", which puts the count where the eye already is.
  • Face thumbs are 46px squares with a 2px speaker ring — correct. The dashed next-person slot is correct. Both should sit in a 3-up grid at 35% opacity for the empty slot, not flex-wrap.
  • The closing reassurance paragraph is doing two jobs (how long, and what closing the tab does). Split it, or cut the second half — the notification permission already covers it.
4 · Name them features/faces/CastScreen.tsx

This is the screen where the design most wants one thing on screen at a time, and the code can show five. In the worst case — a voice with no face, plus two match notes, plus three people — the card stacks a quote block, a no-face card with its own input, a warn list, a two-row face grid and a footer, and the primary action ends up below the fold on a laptop. The question being asked is "who is this?"; everything that isn't evidence for that answer should be one line, not a card.

  • Rule break: play/pause are the ▶ / ❚❚ characters, and the waveform bars are a hardcoded OKLCH literal that won't flip to light mode. Both are drawn above.
  • Collapse the no-face card into the empty-slot option it duplicates — the fourth grid cell already says "Someone we didn't see / They stay wide". Name-anyway becomes an input revealed on that cell, not a second card above it.
  • The face grid is grid-cols-3 plus a 4th cell, so with three people the "didn't see" option lands alone on a second row. Make it a flex row of equal cards that wraps as a unit.
  • Evidence block sits on raised; spec is chrome at r-card-lg. The 16px/25px quote is correct.
  • "Who is this?" → "Who's speaking here?", and VOICE 1 OF 2 → quiet mono voice 1 of 2. The uppercase label is reserved for machine micro-labels; a progress count in caps reads as a warning.
  • "Previous voice" is an underlined text link — the system has no underlined links. Ghost button.
5 · Edit features/timeline/EditorView.tsx · 1344 lines BIGGEST WIN

The transcript pane is the best-built thing in the codebase: 404px to the token, the 3px state rail with the right precedence, 13.5/22 on the selected turn and 12.5 elsewhere, speaker dots at 7px, warn chips for NO FACE and TALKING OVER, and a one-clause reason under every line exactly as the voice rule asks. The stage and the timeline are solid. The bottom bar is where it falls apart.

With a shot selected, one wrapping flex row holds up to sixteen controls: the shot label, a person toggle per cast member, two timecode inputs, Split, Go wide, four nudge arrows, Reset crop, then a framing select, a trim checkbox, Undo, Redo, Reset to suggested and Export episode. They are all the same size, the same border, the same ink. "Export episode" — the one accent action on the screen, and the thing that ends the session — is the sixteenth item in a row of visually identical buttons. Nothing tells the eye where selection-scoped controls end and episode-scoped ones begin, and on a 1280px window the row wraps mid-group.

  • Split the bar in two. Left: what's selected — label, who's on screen, times, Split, Go wide, Nudge. Right, separated by the 1px line already used inside the group: what's the episode's — framing style, trim, undo/redo, reset, and Export as the only primary. Give the right group a fixed order that never wraps into the left.
  • The nudge cluster is four 24px arrow-character buttons. Make it one labelled 4-way pad drawn in CSS, or fold it into a small popover off "Nudge crop" — it's fine adjustment, not a top-level control.
  • Rule break: bg-black on the stage, the pane fallback and every split divider → plate-b ground with plate-a dividers, so the plate lifts in light mode instead of punching a hole. text-white/80 on the media error → plate-ink. Play/pause characters again. shadow-lg on the shortcuts popover.
  • The title bar drops two things the design carries: the three 11px traffic lights, and the mono "service ok" label beside the health dot. A bare 7px dot with a title attribute is not legible state — that dot is the only signal that the thing doing all the work is alive.
  • The review counter packs a square, a count, and two ‹ › steppers into one 10px mono pill with ml-1/mr-1 nudges holding it together. Rebuild as label + two quiet 24px steppers with real gap.
  • The framing select and the trim checkbox are unstyled browser controls — the only two in the product. The checkbox renders as the OS blue, which is the one place a non-palette colour appears anywhere in the app.
6 · Publish features/publish/PublishScreen.tsx

Structurally the most faithful screen in the app — the honest manifest with unbuilt artefacts shown rather than hidden, the destination line stating the one exception to the local-first promise out loud, the four render states, and the ffmpeg warning arriving before the render rather than after. All of that is the credibility block and it's intact. The gap is entirely in the marks on the page.

  • Rule break: the tick SVG is strokeWidth 3.5 against a system whose only icon rule is 1.5px stroke, no fill. Use the literal check character in Instrument Sans 700 — rendered above.
  • Unbuilt artefacts carry opacity-70 and destinations opacity-60, which reads as "broken" rather than "not yet". Full-opacity row, outline chip, beta tokens on the badge — the honesty lands harder when it isn't whispered.
  • The unchecked ring is a literal oklch(0.42 0.01 80) at 2px. Token it, and drop to the 1px border weight the rest of the system uses.
  • The BETA badge is 9px — under the 9.5px mono floor — in control/text-3 instead of the beta pair.
  • The CLIPS column is a 9:16 dashed box reading "Not built yet" beside a paragraph explaining the heuristic — a third of the body width spent on an empty rectangle. The design's striped placeholder with a mono caption says the same thing and looks deliberate; or drop the box and keep the sentence.
  • "Save a draft" is disabled with a dashed border; the render % readout is a disabled button. Both are inert, not disabled — and the percentage isn't a button at all; it's a timecode.
7 · The two dead ends NoFacesScreen.tsx · ProcessingFailed.tsx

Both follow the four-beat error pattern properly, keep the raw message in the mono well beneath the plain line, and offer a way forward and a way out. The copy is on-voice. Only three things to change: border-warn/45 → the warn-edge token, the 13px buttons → the ladder, and "Pick a different file" as an underlined text link → ghost button. The system documents eight edge cases through one card component; these two are hand-built versions of it, so factoring them into a shared card is what keeps the ninth one honest.

Where to start

Seven files close most of the list. Six of them don't exist yet, and none of them are a design decision.

1 Finish index.css

Flip the base layer to dark, add the seven missing token families, register the spacing scale and the type scale as named keys. No component changes. This alone kills S1, S2, S9 and makes S4's 13px impossible to type by accident.

2 Add components/ui

Six files: Button, Chip, Card, SectionLabel, PlayButton, StageRow. Every one of them already exists in the design system as JSX with the exact values — they're a port, not a design task. That's S3 through S8, and about 400 lines of ad-hoc className deleted.

3 Then the two layouts

Only two screens need real design work once the primitives land: the editor's bottom bar split into selection-scoped and episode-scoped groups, and the cast screen collapsed back to one question at a time. Say the word and I'll build both as working screens against the ported components.
